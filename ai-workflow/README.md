# 多AI协作交接入口

创建：2026-10-21。目标：规划、执行、回报、下一步在同一个仓库中接力，减少复制整段聊天。

## 总体指引与目录

| 目录 | 放什么 | 主要维护者 |
|---|---|---|
| 00-总体指引.md | 分工、预算、20:00/20:30自动文件交接与提交边界 | Codex维护，两端执行 |
| 01-plans | 目标、优先级、约束、验收与阶段安排 | Codex维护主计划；执行者可提出短建议 |
| 02-tasks | 已拆好的可执行任务卡 | 日常助教可细化小步骤，重大变化交Codex |
| 03-progress | 实际改动、运行结果、用户解释、问题和复核意见 | 执行者写回报，Codex按需追加复核 |
| 04-next | 当前任务、执行者、状态、下一步 | 交接双方根据证据更新，作为唯一汇总来源 |
| 05-handoff | 千问给Codex的当日交接清单 | 千问写入，Codex定时读取 |

开始先读[每日协作总体指引](00-总体指引.md)，再读[当前状态与下一步](04-next/当前状态与下一步.md)，需要整体背景再看[当前主计划](01-plans/当前主计划.md)。

## 工作方式

1. 读状态，核对用户最新说明及工作区改动。
2. 找到任务卡，在04-next中填写执行者并将任务改为进行中。已有执行者时不要另开同一任务。
3. 一次做25—45分钟的小步骤；任务卡可以分多次完成，不无限扩展。
4. 在03-progress复制[回报模板](03-progress/回报模板.md)，保存为“日期-任务ID-执行者-序号.md”，例如2026-10-23-C01-qwen-01.md。每次新建文件，保留历史。
5. 填实际结果及本人能否解释。普通练习有输出且解释通过可验收；关键协议、选题、异常结果或排错无进展时，标待复核。
6. 更新04-next，只指定一个主要代码下一步。课程台账或等待外部回复可以并行。
7. 平时可手动发起“读取仓库最新状态并继续”。每日固定由千问20:00落盘、Codex20:30读取；两端由各自应用调度，不直接转发聊天或互相唤醒。具体输出与缺交处理见总体指引。

状态：待核验 / 待开始 / 进行中 / 已运行待解释 / 待复核 / 已验收 / 阻塞。

## 复核规则

- 执行者自检通过、用户解释通过、Codex复核通过是不同记录，不混写。
- Codex接到回报后先检查证据，再在同一回报文件的“复核区”追加结论，记录实际读过的文件/输出；未重跑就注明未重跑。
- 普通小练习无需逐项交Codex。复杂研究和关键评估等待复核后再推进其依赖任务。
- 同一问题两轮实质排查或约30分钟仍无进展，整理最小代码、完整错误、已尝试步骤再交接。
- 不修改过去的实验数字来匹配计划；没有结果时写未运行。

## 公开与本地

此仓库公开，只放技术任务、匿名结果和必要进度。个人课表、学号、导师/师兄原话、个人申请策略等存到03-progress/本地私有/或仓库外。该子目录已加入.gitignore，不随常规提交上传；其他AI需要本地访问权限才能读取。

若执行工具不能访问本地文件，让它给出按模板填写的短回报，由用户保存。不能因此声称文件已经更新。共享目录本身也不提供自动并发锁。

## 给千问或Trae的启动指令

> 请先读AGENTS.md、ai-workflow/00-总体指引.md和ai-workflow/04-next/当前状态与下一步.md。认领一个任务，按对应任务卡执行一小步。结束后保存真实进度回报并更新下一步；复杂问题标待复核，不把未运行代码当成果，不重复生成整套计划。

## 给Codex的接手指令

> 请读取ai-workflow/04-next/当前状态与下一步.md及其指向的最新待复核回报，检查实际文件和证据，追加复核意见并更新下一步。先处理当前问题，不重写整套成长规划。

## 每晚自动交接

已配置的时间为北京时间20:00/20:30，复用现有日报和交接文件。每日公开文档由Codex检查后提交推送，千问不推送。电脑和相关应用需在运行；应用执行历史才是调度证据，详细说明见[总体指引](00-总体指引.md)。
